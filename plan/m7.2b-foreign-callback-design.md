# M7.2b design — host foreign-function callbacks + `doodle_call_block`

The last M7.2 piece and the one genuinely hard soundness spot (FFI review C-3):
a **host (C) foreign function** whose synchronous callback runs inside the
engine and may **call back in** to invoke its block argument. This proves the M7
accept criterion — *a foreign function with a default parameter and a block
parameter, both binding per L§8.3, registered through the C ABI*.

Written with the review context fresh (pre-compaction). Execute from this doc.

## The hard problem (control inversion)

`doodle_drive` holds `&mut Instance` on the Rust stack. A foreign function's
callback is invoked *from inside* that drive; if the callback calls
`doodle_call_block`, that must **not** reconstruct a second `&mut Instance` from
the instance pointer — two live `&mut Instance` is instantaneous UB (Stacked/Tree
Borrows), independent of any data race. The block invocation must route through
the **`&mut IntrinsicCtx`** the engine already threaded down (which itself holds
`&mut Machine` / `&mut Heap`), never through the `DoodleInstance`.

Also: `IntrinsicFn = fn(&mut IntrinsicCtx) -> Result<Option<Value>, Raise>` is a
bare `fn` pointer (can't carry a host `void*`), and every `IntrinsicCtx` accessor
is `pub(crate)`. So this needs an **engine change**, not just capi marshalling.

## Engine change (doodle-core)

Ground truth (verified): `IntrinsicCtx<'a>` holds `resolved`, `heap: &mut Heap`,
`machine: &mut Machine`, `modules: &mut [LoadedModule]`, `args: Vec<Value>`,
`block: Option<BlockDescriptor>`, `call_span`. `invoke_block(&mut self, args:
Vec<Value>) -> Result<BlockResult, Raise>` exists (`BlockResult::Completed /
NonLocalExit / Halted`). `ForeignBody` = `Sync(IntrinsicFn) | Capability`.
`Machine` owns the handle table (`machine.handles`).

1. **New `ForeignBody` variant** carrying a type-erased, `Send` host callback:
   ```rust
   ForeignBody::Host(HostCallback)
   // pub type HostCallback = Box<dyn Fn(&mut IntrinsicCtx) -> Result<Option<Value>, Raise> + Send>;
   ```
   `apply`/`step` dispatch it exactly like `Sync` (run inline, same reentrancy,
   same S-46/S-15 backstops — `apply` already faults a callback that drives after
   a `NonLocalExit` or returns a value then; keep that path). Keep the callback
   `Fn` (not `FnMut`) so it is re-callable and `Send` is easy; the capi closure
   captures only the C fn pointer + `void*` (both `Send`, via a `SendPtr`
   newtype the capi owns — the capi is the AD1 unsafe crate).

2. **Public host-call surface on `IntrinsicCtx`** — the minimal API the capi
   trampoline needs, added as `pub` (or a `pub` inherent `impl` block distinct
   from the `pub(crate)` engine helpers):
   - `pub fn arg_count(&self) -> usize`
   - `pub fn arg_handle(&mut self, i: usize) -> Option<Handle>` — interns the
     i-th arg **Value** into a host-owned **Handle** (via `machine.handles`), so
     the C callback reads it with the ordinary `doodle_as_*`. The host releases
     it.
   - `pub fn resolve_handle(&self, h: Handle) -> Option<Value>` and
     `pub fn intern(&mut self, v: Value) -> Handle` — for `invoke_block` args and
     the result/raise value (handle ⇄ Value against the same table).
   - `pub fn invoke_block_handles(&mut self, args: &[Handle]) -> Result<BlockResult, Raise>`
     — resolves the handles to Values, calls the existing `invoke_block`.
   - `pub fn emit(&mut self, bytes: &[u8])` (promote the existing one).
   - Keep `BlockResult` reachable (a `pub` mirror enum or make it `pub`).
   Do **not** expose `heap`/`machine`/`modules` raw — only the curated calls, so
   the capi never touches engine internals directly.

3. **Public foreign-function builder** (so capi can construct the descriptor).
   Prefer a small `pub` builder over exposing `ForeignParam`/`Intrinsic` fields:
   ```rust
   pub struct ForeignBuilder { name, kind: BodyKind, params: Vec<ForeignParam> }
   impl ForeignBuilder {
       pub fn new(name, kind) -> Self
       pub fn param(self, name) -> Self               // required
       pub fn default_param(self, name, ConstValue) -> Self  // immutable default (D-M7-8)
       pub fn block_param(self, name) -> Self          // trailing block
       pub fn host(self, callback: HostCallback) -> Intrinsic  // finish
   }
   ```
   (`Intrinsic::capability` from M7.2a is registered via `add_builtin` today; a
   generic `ForeignBuilder::capability(self)` can be added later if a host needs a
   custom capability — not required for M7.2b.)

Native test in doodle-core: a `ForeignBody::Host` closure with a default + block
param, driven, binds per L§8.3 and invokes its block — proving the mechanism
before any C. (Mirror the existing `greet_with_default` M7.0 test, but with a
`HostCallback` closure instead of the `Sync` fn pointer.)

## C surface (doodle-capi)

- `DoodleForeignDesc` opaque builder (D-M7-7):
  `doodle_foreign_desc_new(name, len, DoodleBodyKind)` →
  `doodle_foreign_desc_param(desc, name, len)` /
  `doodle_foreign_desc_default_int|float|bool|nil|string|bytes(desc, name, len, value…)`
  (each → a `ConstValue`; no handle, since registration predates the heap) /
  `doodle_foreign_desc_block_param(desc, name, len)` /
  `doodle_foreign_desc_set_callback(desc, DoodleForeignFn, void* user_data)`.
  `doodle_registry_add_foreign(reg, desc)` consumes the desc, builds the
  `HostCallback` closure, registers the `Intrinsic`.
- `DoodleBodyKind` enum: `Proc = 0, Func = 1`.
- `DoodleForeignFn` typedef:
  `DoodleStatus (*)(DoodleCallCtx* ctx, void* user_data)`.
- `DoodleCallCtx` **opaque** = a `*mut IntrinsicCtx` (a capi wrapper holding the
  raw ctx pointer). **Valid only for the dynamic extent of the callback.** The
  callback API:
  - `doodle_call_arg_count(ctx) -> uint32_t`
  - `doodle_call_arg(ctx, i, DoodleHandle* out)` — host-owned handle; release it.
  - `doodle_call_block(ctx, const DoodleHandle* args, uint32_t n, DoodleBlockOutcome* out)`
    — invokes the block reentrantly through **`IntrinsicCtx::invoke_block_handles`**
    (never a second `&mut Instance`). `DoodleBlockOutcome` = `Completed = 0 |
    NonLocalExit = 1 | Halted = 2`.
  - `doodle_call_emit(ctx, const uint8_t* bytes, size_t len)` — output.
  - `doodle_call_set_result(ctx, DoodleHandle)` — the `fn` result.
  - `doodle_call_set_raise(ctx, DoodleHandle)` — raise this value at the call site.
- The trampoline (the `HostCallback` closure the capi builds): wraps the
  `&mut IntrinsicCtx` as a `DoodleCallCtx`, calls the C `DoodleForeignFn`, and
  maps its outcome:
  - `set_result(h)` → `Ok(Some(resolve_handle(h)))`; nothing set on a `to` →
    `Ok(None)`; `set_raise(h)` → `Err(Raise{value})`.
  - The callback **must return promptly** (no result) after a `doodle_call_block`
    that reported `NonLocalExit`/`Halted` — enforced by the engine's existing
    apply-site backstop (S-46/S-15); a C host that violates it faults
    `NestedSuspend`/`Internal`, not UB.

## Soundness (the whole point)

- **No second `&mut Instance`.** `DoodleCallCtx` *is* the `&mut IntrinsicCtx`
  (raw pointer). `doodle_call_block` calls `IntrinsicCtx::invoke_block_handles` on
  that pointer. The instance pointer is never touched inside the callback, so the
  outer `doodle_drive`'s `&mut Instance` stays the only one.
- **Lifetime.** The `DoodleCallCtx` is valid only while the C callback runs.
  Stashing it and calling later is caught, not UB: tag the capi ctx wrapper with a
  one-shot liveness flag flipped off when the trampoline returns; every
  `doodle_call_*` checks it (→ `ErrContract`). (The raw `IntrinsicCtx` pointer is
  on the Rust stack during the call; after the call it is gone — the flag stops a
  dangling deref.)
- **Panic across the nested callback.** The `HostCallback` closure runs inside
  the engine's `step`; a panic there must not cross the FFI. Wrap the C-fn call in
  `catch_unwind` inside the trampoline; a caught panic becomes a `Raise` (or a
  distinguished fault) so the drive unwinds cleanly rather than UB.
- **S-19 determinism.** The callback is a synchronous foreign function → must be
  deterministic (E§5.2, landed M7.1). Documented at the descriptor.
- **`Send`.** The closure captures a `SendPtr(*mut c_void)` + an
  `extern "C" fn` — both made `Send` by the capi (AD1). `Instance: Send` holds.

## Order of work

1. doodle-core: `ForeignBody::Host` + `HostCallback` + the curated `pub`
   `IntrinsicCtx` host-call API + `ForeignBuilder`; native test. Land.
2. doodle-capi: `DoodleForeignDesc` builder (`desc.rs`), `DoodleCallCtx` + the
   call API + trampoline (`call.rs`), `doodle_registry_add_foreign`; the
   accept-criterion test (a host `greet(who="world", block)` through C: omitted
   arg → default, block invoked). Extend the C smoke host with a foreign fn.
   Regenerate `doodle.h`. Land.
3. **Review pass** (read-only, FFI-soundness lens) on the `&mut` aliasing, the
   `DoodleCallCtx` liveness, and panic-across-callback **before** the final land.
